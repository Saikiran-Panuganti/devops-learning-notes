# Returning Values from Bash Functions

## Purpose

> **Returning values from functions helps determine whether a task was
> successful and allows the script to use the function's output for further
> actions.**

## DevOps Perspective

In DevOps, functions often perform critical tasks such as:

- Checking server health
- Validating deployments
- Verifying service status
- Testing connectivity
- Monitoring application availability

The returned value helps decide the next step in the automation workflow.

## Real-Time DevOps Example

### Service Health Check

This function checks whether the `nginx` service is active. It requires
permission to query the service on the target system.

```bash
check_service() {
    systemctl is-active nginx >/dev/null
    return $?
}
```

`systemctl is-active` sets an exit status: `0` when the service is active and a
non-zero status when it is not. `$?` contains the exit status of the most
recent command, so `return $?` passes the status from `systemctl` back to the
function's caller. It must come immediately after `systemctl` because another
command would change `$?`.

Use the function's status to decide what to do next:

```bash
if check_service; then
    echo "Service is running. Continue deployment."
else
    echo "Service is not running. Stop deployment and alert the team." >&2
    exit 1
fi
```

For this check, status `0` means the service is active; a non-zero status means
it is not active or the check could not confirm that it is active.

---

Bash functions can produce output and report whether they succeeded. These are
two different things:

- **Output** is text or data written by the function.
- **Exit status** is a small status code that tells the caller whether the
  function succeeded. By convention, `0` means success and a non-zero value
  means some kind of failure.


## Return an exit status

Use `return` to end a function and set its exit status:

```bash
check_number() {
    if [ "$1" -gt 0 ]; then
        return 0
    else
        return 1
    fi
}

if check_number 5; then
    echo "The number is positive."
else
    echo "The number is not positive."
fi
```

The `if` statement checks the function's exit status directly. A status of `0`
means the condition succeeds; a non-zero status means it fails.

You can also read the most recent command's status using `$?`:

```bash
check_number 5
status=$?
echo "Function status: $status"
```

Store `$?` immediately after the function call. Any later command changes what
`$?` refers to.

## Produce a value as output

`return` is not for returning a calculation such as `8`, nor is it for returning
text. To provide a value, print it and capture the output with command
substitution:

```bash
add_numbers() {
    local result
    result=$(("$1" + "$2"))
    printf '%s\n' "$result"
}

sum=$(add_numbers 5 3)
echo "The sum is: $sum"
```

Output:

```text
The sum is: 8
```

`$(...)` runs the function and captures its standard output. `printf` is used
here to print the result.

## Keep output and status separate

If a function needs to provide both a value and a success/failure status, print
the value and return a status:

```bash
divide() {
    if [ "$2" -eq 0 ]; then
        echo "Error: cannot divide by zero." >&2
        return 1
    fi

    printf '%s\n' "$(($1 / $2))"
}

if result=$(divide 12 3); then
    echo "Result: $result"
else
    echo "The calculation failed."
fi
```

The value is captured in `result`; the `if` checks the function's status.

## Remember

- Use `return 0` for success and a non-zero status for failure.
- Bash exit statuses are in the range `0` through `255`. They are status codes,
  not general-purpose return values.
- Use printed output and command substitution (`value=$(function_name)`) to
  capture text or calculation results.
- Avoid printing extra informational messages to standard output when that
  output is meant to be captured. Send diagnostics to standard error with
  `>&2`.
