# Using `trap` for Signals and Cleanup in Bash

## What is a signal?

A signal is a notification sent to a running process. For example, pressing
Ctrl+C in a terminal sends the interrupt signal (`SIGINT`). A script can use
Bash's `trap` command to respond to selected signals or to run a command when
the script exits.

## Basic `trap` syntax

```bash
trap 'commands_to_run' SIGNAL
```

The action is written in quotes and runs when Bash receives the named signal.
Use single quotes so Bash expands variables when the trap runs, not when the
trap is first set.

## Handle Ctrl+C with `SIGINT`

```bash
#!/usr/bin/env bash

handle_interrupt() {
    echo "Script interrupted (Ctrl+C)." >&2
    exit 130
}

# Run handle_interrupt if the user presses Ctrl+C.
trap 'handle_interrupt' INT

echo "Running. Press Ctrl+C to stop."
while true; do
    sleep 1
done
```

`SIGINT` is commonly sent when the user presses Ctrl+C. Exit status `130` is a
conventional status for a process stopped by `SIGINT`.

## Clean up when a script exits

The `EXIT` trap runs when the shell is about to exit, whether the script
finishes normally or exits with an error:

```bash
#!/usr/bin/env bash

temporary_file=$(mktemp)

cleanup() {
    rm -f "$temporary_file"
    echo "Temporary file removed."
}

# Register cleanup as soon as the temporary file has been created.
trap 'cleanup' EXIT

echo "Temporary data" > "$temporary_file"
echo "Working with temporary file: $temporary_file"
```

Register cleanup soon after creating temporary resources. This helps prevent
temporary files from being left behind if the script exits early.

## Handle a termination request and clean up

`SIGTERM` is commonly used by another process or the operating system to ask a
program to stop. A script can handle it and then exit:

```bash
#!/usr/bin/env bash

cleanup() {
    echo "Cleaning up before exit."
}

handle_termination() {
    echo "Termination requested." >&2
    exit 143
}

trap 'cleanup' EXIT
trap 'handle_termination' TERM

echo "Waiting for work..."
while true; do
    sleep 1
done
```

The `EXIT` trap runs when `handle_termination` exits the script. `143` is a
conventional exit status for termination by `SIGTERM` (`128 + 15`).

Do not ignore `SIGTERM` by default. Services and job runners use it to request
graceful shutdown. Ignoring it can prevent a process from stopping when
expected. If a signal truly should be ignored, Bash can do so with:

```bash
trap '' TERM
```

Use this only when there is a specific reason to ignore the termination
request.

## The `ERR` trap

Bash's `ERR` trap can run an action when a command fails in many situations:

```bash
#!/usr/bin/env bash

handle_error() {
    echo "A command failed." >&2
}

trap 'handle_error' ERR

some_command_that_might_fail
```

The `ERR` trap has exceptions and follows rules similar to `set -e`; it does
not run for every non-zero status. For example, a command used as an `if`
condition may return non-zero intentionally. Use explicit `if` checks when a
failure needs specific handling:

```bash
if some_command_that_might_fail; then
    echo "Command succeeded."
else
    echo "Command failed; taking the expected recovery action." >&2
fi
```

An `ERR` trap also does not automatically stop the script. Use `exit` in the
handler if stopping is the intended behavior.

## Combining traps

A script can set traps for different events:

```bash
trap 'cleanup' EXIT
trap 'echo "Interrupted." >&2; exit 130' INT
trap 'echo "Termination requested." >&2; exit 143' TERM
```

Keep the cleanup function safe to run once, and avoid putting lengthy or
unreliable work inside a signal handler. A signal can interrupt the script at
an unexpected point.

## Key points

- `trap` lets a Bash script respond to signals and exit.
- `INT` is commonly sent by Ctrl+C; `TERM` requests that a process stop.
- Use `EXIT` for cleanup that should happen whenever the script exits.
- `ERR` has exceptions and should not replace explicit checks for important
  commands.
- Avoid ignoring `TERM` unless the script has a deliberate reason to do so.
