# Basic Shell Commands for Everyday DevOps Work

## Definition

Shell Commands are instructions entered in a shell (such as Bash) to perform specific tasks like file management, process control, system administration, and automation.

## Purpose

Shell commands let users and scripts interact with the operating system
efficiently and automate repetitive tasks.

### DevOps perspective

In DevOps, shell commands are used to:

- Manage files and directories.
- Monitor system performance.
- Deploy applications.
- Manage servers and cloud resources.
- Automate CI/CD pipeline activities.
- Troubleshoot infrastructure issues.

> **Safety:** Practice in a test directory or lab system. Commands such as
> `rm`, `mv`, package managers, and service-management tools can change a
> system. Check paths and command options before running them.

## 1. Find your location and identify yourself

| Command | What it does |
| --- | --- |
| `pwd` | Prints the current working directory |
| `whoami` | Prints the current username |
| `id` | Shows the current user's ID and group memberships |
| `hostname` | Prints the system's host name |
| `uname -a` | Shows kernel and system information |

Example:

```bash
pwd
whoami
hostname
```

Knowing the current directory and user helps avoid running commands in the
wrong place or with unexpected permissions.

## 2. Navigate directories

| Command | What it does |
| --- | --- |
| `ls` | Lists files and directories |
| `ls -l` | Shows a detailed listing |
| `ls -la` | Includes hidden files |
| `cd DIRECTORY` | Changes to a directory |
| `cd ..` | Moves to the parent directory |
| `cd ~` | Moves to your home directory |

Examples:

```bash
ls -la
cd /var/log
pwd
cd ~
```

Use `cd -- DIRECTORY` when a path starts with a dash. Quote paths that contain
spaces, for example `cd "project files"`.

## 3. Create and manage files and directories

```bash
mkdir practice
touch practice/notes.txt
cp practice/notes.txt practice/notes-backup.txt
mv practice/notes-backup.txt practice/backup.txt
```

- `mkdir` creates a directory. Use `mkdir -p path/to/directory` to create
  missing parent directories too.
- `touch` creates an empty file if it does not exist, or updates its timestamp
  if it does.
- `cp SOURCE DESTINATION` copies a file.
- `mv SOURCE DESTINATION` moves or renames a file.

### Remove files carefully

```bash
rm practice/backup.txt
rmdir practice/empty-directory
```

`rm` removes files, and `rmdir` removes an empty directory. Removed files may
not be recoverable. Always check the target path before using `rm`; avoid
practicing with broad or recursive deletion commands.

## 4. Read and search text files

| Command | Typical use |
| --- | --- |
| `cat FILE` | Prints a small file |
| `less FILE` | Reads a file page by page; press `q` to quit |
| `head -n 20 FILE` | Prints the first 20 lines |
| `tail -n 20 FILE` | Prints the last 20 lines |
| `tail -f FILE` | Follows new lines added to a file; press Ctrl+C to stop |
| `grep "TEXT" FILE` | Prints lines containing matching text |

Examples:

```bash
less /etc/os-release
grep "ERROR" application.log
tail -n 50 application.log
```

To follow an application log while reproducing an issue:

```bash
tail -f application.log
```

Use `grep -i` for a case-insensitive search and `grep -n` to include line
numbers:

```bash
grep -in "timeout" application.log
```

## 5. Find files

`find` searches for files and directories under a starting path:

```bash
find . -name "*.log"
find /var/log -type f -name "*.log"
```

- `.` means the current directory.
- `-type f` searches for regular files.
- `-name "*.log"` matches names ending in `.log`. Keep the pattern quoted so
  the shell does not expand it before `find` receives it.

## 6. Check disk, memory, and system load

| Command | What it shows |
| --- | --- |
| `df -h` | Disk space for mounted filesystems, in readable units |
| `du -sh PATH` | Total space used by a path |
| `free -h` | Memory and swap usage |
| `uptime` | How long the system has been running and load averages |

Examples:

```bash
df -h
du -sh /var/log
free -h
uptime
```

If a disk is filling up, `df -h` helps identify the affected filesystem.
`du -sh` can then help inspect the size of a specific directory.

## 7. Inspect processes

```bash
ps aux
ps aux | grep nginx
top
```

- `ps aux` lists running processes.
- `grep` filters that list for text such as a process name.
- `top` displays a live, updating process view; press `q` to quit.

The `grep` example may also show the `grep` command itself. On systems with
`pgrep`, use `pgrep -a nginx` to search for matching process names.

## 8. Check services and logs

On systems that use `systemd`, `systemctl` checks service state and `journalctl`
reads system logs:

```bash
systemctl status nginx
journalctl -u nginx --since "1 hour ago"
```

These commands inspect service state and logs. Starting, stopping, or
restarting services changes system state and may require administrator
permissions:

```bash
sudo systemctl restart nginx
```

Only restart a service when you understand the impact and are authorized to
do so.

## 9. Check network connectivity

```bash
ip addr
ip route
```

- `ip addr` lists network interfaces and their addresses.
- `ip route` shows the system's routing table.

To check whether a web endpoint responds, `curl` can print response headers:

```bash
curl -I https://example.com
```

Use an endpoint you are authorized to access. A network failure can have
several causes, so check the command's output and exit status rather than
assuming the application is at fault.

## 10. Understand command success and failure

Commands return an exit status. Usually, `0` means success and a non-zero
value means failure:

```bash
grep -q "ERROR" application.log
echo "$?"
```

`$?` contains the status of the most recently executed command. In scripts,
prefer checking the command directly:

```bash
if grep -q "ERROR" application.log; then
    echo "Errors were found."
else
    echo "No matching errors were found."
fi
```

See [Error handling in Bash](../10.error-handling/1.error-handling.md) for
more on exit statuses and handling failures.

## 11. Combine commands with pipes

A pipe (`|`) sends one command's standard output to another command:

```bash
grep "ERROR" application.log | wc -l
```

This prints the number of lines containing `ERROR`. Pipes are useful for
filtering and summarizing command output without creating an intermediate
file.

## A simple troubleshooting workflow

When an application appears unavailable, start with read-only checks:

```bash
# Confirm which system and user you are working with.
hostname
whoami

# Check whether the service is active.
systemctl status nginx

# Review recent service messages.
journalctl -u nginx --since "15 minutes ago"

# Check disk space and network configuration.
df -h
ip route
```

These commands gather information without restarting the service or changing
configuration. Decide on a change only after reviewing the findings and
following your team's operational procedures.

## Quick reminders

- Use `pwd` and `ls -la` to orient yourself before changing files.
- Quote paths and variable expansions when they may contain spaces.
- Read command help with `command --help` or a manual page with `man command`.
- Review paths and options before commands that modify or delete data.
- Use `sudo` only when administrator privileges are needed and permitted.
- Prefer read-only inspection first when troubleshooting production systems.
