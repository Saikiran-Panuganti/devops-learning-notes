## Definition

An **Ansible inventory file** lists the target servers (managed nodes) that
Ansible can connect to and manage.

> **Inventory file = Ansible's address book for servers**

An inventory tells Ansible which hosts are available and how they are grouped.
It can include hostnames, IP addresses, and connection details.

## Real-Time Example

Imagine you are a DevOps engineer managing:

- 2 web servers
- 2 database servers

Without an inventory file, you would have to provide server addresses whenever
you run a command. Instead, put the hosts in an inventory and organize them
into groups. You can then target one server, a group, or all the servers.

Create a file named `inventory.ini`:

```ini
[web]
web1.example.com
web2.example.com

[database]
db1.example.com
db2.example.com
```

Replace the example hostnames with the hostnames or IP addresses of your
servers. The group names (`web` and `database`) are labels you choose.

## Using the Inventory

Use `-i` to tell Ansible which inventory file to read. For example, list the
hosts in the inventory:

```bash
ansible all -i inventory.ini --list-hosts
```

Target only the web servers:

```bash
ansible web -i inventory.ini --list-hosts
```

Ansible also supports YAML inventory files. INI is a common, simple format
for getting started.

## Why Use an Inventory File?

- Keep server addresses in one place.
- Group servers by role or environment.
- Run tasks against selected hosts or groups.
- Reuse the same host list across Ansible commands and playbooks.
