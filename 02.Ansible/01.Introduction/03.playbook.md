# What Is an Ansible Playbook?

## Definition

An **Ansible playbook** is a YAML file that describes one or more plays. A play
maps a group of hosts to a sequence of tasks that Ansible runs on those hosts.

> **Playbook = A repeatable set of automation instructions written in YAML.**

Like a shell script, a playbook automates work. Instead of writing a sequence
of shell commands, you describe the desired outcome using Ansible tasks and
modules.

## Real-Time Example

Suppose you launch new web servers and need to install Apache, start its
service, and make sure it starts automatically after a reboot. Rather than
performing these steps manually on every server, write a playbook and target
the `web` group from your inventory.

Create `apache.yml`:

```yaml
---
- name: Install and start Apache
  hosts: web
  become: true

  tasks:
    - name: Install Apache package
      ansible.builtin.package:
        name: httpd
        state: present

    - name: Start and enable Apache service
      ansible.builtin.service:
        name: httpd
        state: started
        enabled: true
```

In this example:

- `name` describes the play or task.
- `hosts: web` selects the `web` group from the inventory.
- `become: true` runs tasks with elevated privileges, as needed for package
  installation and service management.
- `tasks` lists the work Ansible performs in order.
- `state: present` ensures the package is installed.
- `state: started` ensures the service is running; `enabled: true` configures
  it to start at boot.

This example uses the `httpd` package and service name commonly used on
Red Hat-family Linux systems. Package names may differ on other distributions.

## Run the Playbook

From the directory containing `inventory.ini` and `apache.yml`, first check
the playbook syntax:

```bash
ansible-playbook -i inventory.ini apache.yml --syntax-check
```

Then run it:

```bash
ansible-playbook -i inventory.ini apache.yml
```

Ansible connects to the hosts in the `web` inventory group and applies the
tasks. The managed servers must be reachable and configured with the
appropriate SSH access and privilege escalation.
