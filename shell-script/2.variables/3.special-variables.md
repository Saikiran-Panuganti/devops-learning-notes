# Special Variables

Special variables are predefined variables that provide information about script arguments, process IDs, exit statuses, directories, and execution time. They help automate real-time DevOps tasks without manually defining every variable.

## Important special variables

| Variable | Meaning | DevOps use | Example |
| --- | --- | --- | --- |
| `$0` | Script name or invocation path | Identify which script is running | `./special.sh` |
| `$1`, `$2`, ... | First, second, and later arguments | Pass environment names, filenames, or other inputs | `./deploy.sh staging app.tar.gz` gives `$1=staging`, `$2=app.tar.gz` |
| `"$@"` | All arguments, preserving each as a separate value when quoted | Process multiple inputs safely | `for arg in "$@"; do echo "$arg"; done` |
| `"$*"` | All arguments combined into one word when quoted | Handle arguments together as a single string | `echo "$*"` prints `Hello DevOps` |
| `$#` | Number of arguments | Validate required inputs | `if [ "$#" -lt 2 ]; then echo "Missing arguments"; fi` |
| `$$` | Process ID of the current shell | Identify the running script process | `echo "Script PID: $$"` |
| `$!` | Process ID of the most recently started background job | Track a background task | `sleep 10 & echo "Background PID: $!"` |
| `$?` | Exit status of the most recently completed command | Check command success or failure | `mkdir -p "$HOME/logs"; echo "$?"` |
| `$LINENO` | Current line number in the script | Locate a line during debugging | `echo "Reached line $LINENO"` |
| `$SECONDS` | Seconds since the current Bash shell started | Measure approximate script runtime | `echo "Elapsed: $SECONDS seconds"` |
| `$USER` | Common environment variable containing the current username | Display or use the executing user's name | `echo "Running as $USER"` |
| `$HOME` | Current user's home directory | Locate user-specific files | `echo "$HOME/.ssh"` |
| `$PWD` | Current working directory | Identify the directory the script is running from | `echo "Working directory: $PWD"` |
| `$(realpath "$0")` | Command substitution that prints the resolved path of the script | Locate the script file | `SCRIPT_PATH=$(realpath "$0")` |

## Remember

- `"$@"` preserves each argument separately; `"$*"` combines them into one word.
- Check `$?` immediately after the command whose status you need to inspect.
- Capture `$!` immediately after starting a background process.
- `$PWD` is the current working directory, not necessarily the directory containing the script.
- `$USER` is an environment variable, and `realpath` is an external command; neither is a Bash special parameter.
- `$SECONDS` measures time since the Bash shell started, which may be earlier than the script's start time.
- `$0` may be a relative path or command name; `realpath "$0"` requires `realpath` to be installed and the path to resolve.

`$@`, `$*`, `$#`, `$?`, `$$`, and `$!` are commonly asked about in DevOps interviews.
