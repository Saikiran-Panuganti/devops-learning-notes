# Using Pipes to Connect Commands

## Definition

A pipe (`|`) sends the standard output of one command to the standard input of
another command. This lets commands work together: one command produces data,
and the next command processes it.

```bash
command1 | command2
```

Read this as: “Run `command1`, then give its output to `command2`.”

## Why use pipes?

Pipes help combine small commands into a useful workflow. Instead of saving
intermediate results to several files, you can pass the output directly from
one command to the next.

## A simple example

```bash
printf "pear\napple\norange\n" | sort
```

`printf` prints three lines. The pipe sends those lines to `sort`, which sorts
them alphabetically:

```text
apple
orange
pear
```

## Chain more than two commands

You can use multiple pipes in one command:

```bash
printf "pear\napple\npear\norange\n" | sort | uniq
```

The data flows from left to right:

1. `printf` prints the list.
2. `sort` puts matching lines next to one another.
3. `uniq` removes adjacent duplicate lines.

Output:

```text
apple
orange
pear
```

`uniq` only removes adjacent duplicates, which is why sorting first is useful.

## Filter and count lines

This example searches a text file for lines containing `ERROR`, then counts
the matching lines:

```bash
grep "ERROR" application.log | wc -l
```

- `grep "ERROR" application.log` prints matching lines.
- The pipe sends those lines to `wc -l`.
- `wc -l` prints how many lines it received.

The result is the number of matching log lines. If you need to count filenames
in a directory, use an appropriate file-finding command rather than piping
`ls` output, since filenames can contain spaces and other special characters.

## Process columns with `awk`

`awk` can select fields from each line. For example:

```bash
printf "Mina 25 developer\nRavi 31 operator\n" | awk '{print $1, $3}'
```

Here, `awk` prints the first and third whitespace-separated fields:

```text
Mina developer
Ravi operator
```

## Use a pipe with file redirection

Input and output redirection can be combined with a pipe:

```bash
sort < names.txt | uniq > unique_names.txt
```

- `< names.txt` gives the contents of `names.txt` to `sort`.
- `|` sends the sorted lines to `uniq`.
- `> unique_names.txt` saves the result in `unique_names.txt`, replacing its
  previous contents if it already exists.

## Standard output and standard error

A normal pipe sends **standard output** (file descriptor `1`) to the next
command. It does not send **standard error** (file descriptor `2`) through the
pipe automatically.

To send both standard output and standard error into the next command in Bash,
redirect standard error to standard output before the pipe:

```bash
some_command 2>&1 | less
```

## Pipeline exit status

By default, Bash uses the exit status of the last command in a pipeline. For
example, in `command1 | command2`, the pipeline's status normally comes from
`command2`.

For scripts where failure in any part of a pipeline should count as failure,
enable Bash's `pipefail` option:

```bash
set -o pipefail
```

This is useful for reliable scripts, but it is not required for every
interactive command.

## Remember

- A pipe is written with a single vertical bar: `|`.
- Data flows from the command on the left to the command on the right.
- A pipe sends standard output, not standard error, unless you redirect it.
- The output of one command becomes the input of the next command.
- Use quotes around text patterns and filenames when appropriate.
