# Important Terraform Commands

Run Terraform commands from the directory containing the configuration and
state for the infrastructure you intend to manage.

| Command | Purpose |
|---|---|
| `terraform init` | Initialize the working directory, backend, providers, and modules. |
| `terraform fmt` | Format Terraform configuration files. |
| `terraform validate` | Check configuration syntax and internal consistency. |
| `terraform plan` | Preview the infrastructure changes Terraform proposes. |
| `terraform apply` | Review and apply the proposed infrastructure changes. |
| `terraform show` | Display a human-readable view of the current state or a saved plan. |
| `terraform state list` | List resources tracked in the current state. |
| `terraform destroy` | Plan and delete all resources managed by the current configuration and state. |

## Target a Specific Resource

Terraform normally plans changes across the configuration as a whole. In
unusual situations, you can use `-target` to focus an operation on one
resource. Resource addresses use the form `TYPE.NAME`, as defined in the
configuration.

Preview changes for one resource:

```bash
terraform plan -target=aws_instance.web
```

Apply changes focused on that resource:

```bash
terraform apply -target=aws_instance.web
```

Destroy a specific resource:

```bash
terraform destroy -target=aws_instance.web
```

Replace a specific resource (destroy it and create it again):

```bash
terraform apply -replace=aws_instance.web
```

Review the plan before applying or destroying anything. A targeted operation
may omit other changes that would normally be included in a complete plan.
Terraform recommends using `-target` only for exceptional situations, such as
recovering from an error or addressing a limitation; it is not a substitute
for updating the configuration and applying a full plan.

> **Important:** `terraform state rm` is different from destroying a resource.
> It removes a resource from Terraform state without deleting the real
> infrastructure. Use it only when you intentionally want Terraform to stop
> managing that resource.
