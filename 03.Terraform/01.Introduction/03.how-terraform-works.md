# How Terraform Works

Terraform lets you describe the infrastructure you want in configuration
files. It compares that desired setup with its state and the actual
infrastructure, then determines what changes are needed.

![How Terraform works](https://github.com/Saikiran-Panuganti/Images/blob/main/03.terraform/03.how-terraform-works.jpg)

## Simple workflow

1. **Write** configuration describing the resources you need, such as a
   network or virtual machine.
2. **Initialize** the directory with `terraform init` to set up providers and
   the backend.
3. **Preview** the proposed changes with `terraform plan`.
4. **Apply** the reviewed changes with `terraform apply`.
5. Terraform creates or updates the resources through the provider and
   updates its state to track them.

## How the state file is created

After you approve `terraform apply`, Terraform asks the provider to make the
infrastructure changes. When the apply succeeds, Terraform creates or updates
the state with details such as resource IDs, so it can track those resources
next time. By default, state is saved in `terraform.tfstate`; with a remote
backend, it is saved remotely instead.

In short: **you describe what you want; Terraform plans and applies the
changes needed to make it happen.**
