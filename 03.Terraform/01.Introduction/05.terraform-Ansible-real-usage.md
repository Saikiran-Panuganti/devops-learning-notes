# Real-World Use of Terraform and Ansible

Terraform and Ansible are often used together to deploy applications. Terraform
creates and manages the infrastructure; Ansible configures the servers and
deploys the application.

![Real-world usage of Terraform and Ansible](https://github.com/Saikiran-Panuganti/Images/blob/main/03.terraform/05.terraform-ansible-real-usage.jpg)

## Example: Deploy a Web Application on AWS

Suppose your team needs to deploy a web application on AWS EC2. A typical
workflow is:

### 1. Terraform provisions the infrastructure

Use Terraform configuration to define and create the resources, such as:

- A VPC and its public or private subnets.
- Security groups with only the required network access.
- EC2 instances for the application.
- A load balancer, if the application needs one.

Review the changes with `terraform plan`, then apply the approved plan. Terraform
records the resources it manages in its state.

### 2. Make the provisioned servers available to Ansible

Ansible needs to know which hosts to configure and how to connect to them. Add
the instance addresses to an inventory or generate/update the inventory from
Terraform outputs. Ensure the Ansible control node can reach the instances and
has authorized credentials.

### 3. Ansible configures the servers

Use Ansible playbooks to perform operating-system and application setup, such
as:

- Install Nginx, Java, or other required packages.
- Create application users and directories.
- Configure application dependencies and service settings.
- Create and enable system services.

### 4. Ansible deploys the application

Ansible can then download application artifacts, place or update application
files, apply environment-specific configuration, and restart or verify the
application service.

## In Short

**Terraform provisions the infrastructure. Ansible configures the servers and
deploys the application.** Using each tool for its common strength separates
infrastructure lifecycle management from machine and application
configuration.
