# Advantages of Terraform and Infrastructure as Code

Infrastructure as Code (IaC) means defining and managing infrastructure
through files rather than creating and changing every resource manually.
Terraform provides several benefits for this approach.

## 1. Version Control

Terraform configuration can be stored in GitHub, GitLab, Bitbucket, or another
version-control system.

- Track infrastructure changes over time.
- Review changes through pull requests.
- Keep a history of configuration versions.
- Revert code changes when needed. Reverting code does not automatically undo
  infrastructure changes; review and apply a Terraform plan to reconcile the
  infrastructure.

## 2. Declarative Infrastructure Management

With Terraform, describe the infrastructure you want rather than writing each
step to create it. Terraform compares the configuration with its state and
the provider's view of the resources, then proposes actions in a plan.

## 3. Consistent Infrastructure

The same reusable configuration can help create consistent environments,
such as:

- Development (DEV)
- Quality assurance (QA)
- User acceptance testing (UAT)
- Production (PROD)

Environment-specific values can be supplied separately. This can reduce
configuration differences and the familiar problem: "It works in DEV, but it
doesn't work in PROD."

## 4. Reusable Infrastructure with Modules

Terraform modules let teams organize and reuse infrastructure configuration
across projects and environments. For example:

```text
terraform-project/
├── modules/
│   ├── vpc/
│   ├── ec2/
│   ├── eks/
│   └── security-group/
└── environments/
    ├── dev/
    ├── uat/
    └── prod/
```

Each environment can call shared modules with different input values.

## 5. Dependency Management

Terraform identifies dependencies between resources from their references.
For example, an EC2 instance may use a subnet and security group, and the
subnet may belong to a VPC. Terraform uses these relationships to determine an
appropriate creation, update, and destruction order.

## 6. Infrastructure Lifecycle Management

Terraform providers expose operations for managing resource lifecycles:

| Operation | Purpose |
|---|---|
| Create | Create new infrastructure |
| Read | Retrieve information about infrastructure |
| Update | Modify existing infrastructure |
| Delete | Destroy infrastructure |

Terraform manages these operations using configuration, providers, state, and
execution plans.

## 7. Infrastructure Visibility

Terraform configuration and state help you understand the resources managed
by a particular Terraform state, including:

- Which resources Terraform manages.
- Resource dependencies.
- Tracked resource attributes.
- The configuration used to describe the infrastructure.

> **Important:** Terraform state is not a complete inventory of every resource
> in your cloud account. It tracks resources managed by that Terraform state.
